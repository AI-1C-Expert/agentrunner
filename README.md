# AgentRunner для 1С

**Среда выполнения ИИ-агентов внутри 1С:Предприятие.** Расширение
конфигурации (`.cfe`), которое даёт языковой модели возможность читать
данные информационной базы и готовить документы — под контролем оператора,
через очередь подтверждений.

> ⚠️ **Проект в стадии `0.x`, публичного релиза ещё не было.**
> Не устанавливайте в продуктивную базу без предварительной проверки на
> копии. Обратная совместимость между версиями пока не гарантируется.

---

## Что это даёт

Пользователь пишет задачу обычным текстом — агент выполняет её доступными
инструментами:

> «Проверь неоплаченные счета покупателям за последние 30 дней и подготовь
> письма-напоминания»

Агент найдёт счета, сверит оплаты, соберёт черновики писем — и **остановится,
показав, что собирается сделать**. Ни один документ не будет проведён и ни
одно письмо не уйдёт без явного подтверждения.

---

## Ключевые свойства

| | |
|---|---|
| **Pure 1C** | Никаких внешних компонент и сервисов. Только платформа и БСП. |
| **Подтверждение действий** | Изменяющие операции идут через очередь approval. Tools формируют payload, но не проводят. |
| **Без `Выполнить()`** | Модель не может выполнить произвольный код — только зарегистрированные инструменты. |
| **Аудит** | Каждый запуск, вызов инструмента и решение оператора записаны. |
| **Локальные модели** | Работает с LM Studio / Ollama — данные не покидают периметр. |
| **Маскирование ПДн** | Compliance-режим скрывает паспорт, СНИЛС, телефон, email, ИНН и ключи API в данных для LLM. |

## Требования

- **1С:Предприятие 8.3.26+** (режим совместимости расширения — 8.3.24).
- Конфигурация на базе **БСП**.
- Доступ к LLM: локальная модель либо ключ облачного провайдера.

**Проверено на:** Бухгалтерия предприятия 3.0.
**Не проверено:** УТ 11, ERP 2, ЗУП 3.1 — универсальный слой инструментов
писался конфигурационно-независимым, но финансовые инструменты завязаны на
план счетов и документы БП.

## Установка

1. Скачайте `AgentRunner.cfe` из [Releases](https://github.com/AI-1C-Expert/agentrunner/releases).
2. В 1С: **Конфигурация → Расширения конфигурации → Добавить из файла**.
3. Перезапустите сеанс. При первом запуске откроется **мастер первичной
   настройки**: выбор провайдера, ввод ключа, импорт пресета.
4. Работа с агентом — раздел **Agent runner → Диалог с агентом**.

Из исходников: загрузите `src/` через конфигуратор
(`Загрузить конфигурацию из файлов`) — см. [CONTRIBUTING.md](CONTRIBUTING.md).

## Инструменты агента

Около 34 инструментов по категориям: данные, документы, финансы,
коммуникации, память, платформа, взаимодействие.

**Универсальные** (работают в любой конфигурации на БСП):
`query`, `read_object`, `search_metadata`, `list_catalogs`, `list_documents`,
`get_object_structure`, `search_text`, `find_references`, `aggregate`,
`get_recent_changes`, `get_object_history`, `run_report`, `get_print_form`.

**Прикладные** (ориентированы на БП 3.0):
`search_clients`, `list_unpaid_invoices`, `get_invoice`,
`find_overdue_receivables`, `create_invoice_draft`,
`create_reconciliation_act`, `prepare_reconciliation_email`,
`prepare_payment_reminder_email`.

**Служебные:** `remember`, `recall_memory`, `get_settings`, `set_setting`,
`ask_user`, `get_current_context`.

**Пока не реализованы** (зарегистрированы, но возвращают `not_implemented`):
`get_inventory`, `get_balance`, `query_payments`, `get_sales_report`,
`send_email_draft`, `notify_telegram`, `create_task`.

Свои инструменты добавляются через `ar_ToolПереопределяемый` — без правки
ядра.

## Безопасность

Расширение даёт модели доступ к данным рабочей базы. Перед установкой
прочитайте [SECURITY.md](SECURITY.md) — там модель угроз и ограничения.

Коротко о главном:
- **API-ключи хранятся без шифрования** — защита только правами доступа
  (платформенное `БезопасноеХранилище` в расширении недоступно).
- При облачном провайдере **данные уходят третьей стороне**; для баз с ПДн
  включайте Compliance-режим или используйте локальную модель.
- Поведение инструментов **под ограниченными правами и RLS ещё не
  проверено** полноценным тестом.
